## Audit-first cleanup

[repository_cleanup.py](../../runtime/audit/repository_cleanup.py) runs a fixed local validator with
`shell=False` behavior, parses its diagnostics, verifies the required original
run inventory and compares artifact bytes with existing manifest hashes. A real
hash mismatch stops remediation; the script never modifies a historical manifest.

```powershell
python -B -m runtime.repository_cleanup
```

Default mode is read-only. Missing history returns Python exit 2 and makes
`--apply` fail before changing files. After recovery and a quiescent workspace,
the narrowly bounded apply mode can archive generated bytecode: recognize the
interpreter magic and corresponding source, reject symlinks/junctions/escape,
write exclusive archival copies, fsync, verify SHA-256, recheck the source, then
unlink just that disposable cache file. No recursive deletion or process stop.
Partial archives/receipts are retained if a step fails.

Session/receipt/citation errors are reported as source/schema repair items;
the script does not change active session PIDs or rewrite scientific evidence.
The current missing-evidence condition prevented executing any cleanup here.
Source repair and compatibility of a restored v1 receipt still need their own
review before accepting that handoff. SHA-256 consistency does not authenticate
a manifest if both a manifest and its data were changed by another actor.

## API usage and pricing data flow

```text
existing authorized provider response (final SDK object)
  -> UsageExtractor.from_sdk(response)
  -> MeteredReviewResponse(review_json, TokenUsage)
  -> LLMPlanner usage_sink BEFORE proposal decoding
  -> UsageLedger exclusive call record; seal to hashed ledger.json
  -> MetricsEngine.compute_monetary()
  -> PricingCalculator.quote() with exact Decimal rates
  -> evaluate_all accounting report and manifest
```

[usage_costs.py](../../runtime/evaluation/usage_costs.py) supports OpenAI Responses, OpenAI Chat Completions
and Anthropic Messages usage. It calls `model_dump(mode="json")` on an SDK object
or accepts a detached response dictionary. It never estimates billable tokens
from a local tokenizer. Final response usage is consumed once; incremental
streaming token totals must not be added together.

Example at the existing provider adapter's response boundary:

```python
from runtime.evaluation.usage_costs import MeteredReviewResponse

# sdk_response already exists; minimize_review_response preserves refusals,
# incomplete status and the closed Task-22 tool envelope.
return MeteredReviewResponse.capture(
    sdk_response,
    review_json=minimize_review_response(sdk_response),
    provider="openai",
    api="responses",
    region="global",  # resolved first-party billing geography, not a guess
)
```

The OpenAI response must identify its effective service tier. `auto` and unknown
tiers cannot be silently priced as standard. For Anthropic, supply
`resolved_tier="standard"` when its API omits tier, based on the trusted adapter's
actual billing context. A reported inference geography takes precedence; the
default global card cannot price a US-premium response.

```python
from pathlib import Path
from runtime.planners.llm_planner import LLMPlanner
from runtime.evaluation.usage_costs import UsageLedger
from runtime.evaluation.evaluate_all import report_usage_costs

ledger = UsageLedger(Path("runtime/usage-ledgers"), run_id=run_id)
planner = LLMPlanner(existing_adapter, count_tokens=existing_context_token_counter,
                     usage_sink=ledger.planner_sink)
# Use the application's existing plan/replan lifecycle. No new execution rights.
# Once all attempts are complete:
ledger_path, ledger_sha256 = ledger.seal()
report_dir = report_usage_costs(ledger_path, ledger_sha256, Path("runtime/evaluation-runs"))
```

`request.state.context` binds run and episode identity to the recorder. Accounting
is separate from the closed plan JSON; it does not grant planner execution rights
or change action/target/approval policy. Usage is recorded even if the proposal is
refused, malformed or incomplete. Recorder errors produce static reason codes and
permanently halt further provider calls on that Planner instance.

Existing string-only providers remain compatible. With accounting enabled, a
string-only reply or a timeout records missing usage, preserving uncertainty about
possible charges. Every retried request with its own response ID is a separate
call; retrieving the same response again is idempotent. Conflicting usage or
episode binding for the same provider/response ID is rejected. SDK-internal
automatic retry attempts are not visible here: the transport must emit per-attempt
records or mark those charges unresolved. No raw prompts, keys, cookies or output
bodies are persisted by this recorder.

The CLI reporting path accepts an existing sealed ledger:

```powershell
python -B -m runtime.evaluate_all --usage-ledger <ledger.json> --usage-sha256 <expected-sha256>
```

Replace the angle-bracket arguments with the real ledger path and digest. The
input is hash-checked; each referenced call file is independently hash-checked.
Reports show calls, unknown calls, known token subtotal and complete token cost.
If any call lacks usage or a matching rate/context, the complete total is `null`,
not zero. Replay credits and imported API dollars are never blended or attributed
to unrelated synthetic episodes.

## Exact rates and cost semantics

The example cards were checked against official provider pricing on 2026-10-12;
the snapshot records UTC 10:36:01. Values are **USD per million tokens**:

| Provider / exact model | Effective tier / geography | Input | Cached read | Output | Cache write | 1h write |
|---|---|---:|---:|---:|---:|---:|
| OpenAI / gpt-4.1-mini | default / global | 0.40 | 0.10 | 1.60 | unsupported | unsupported |
| Anthropic / claude-sonnet-4-6 | standard / global | 3.00 | 0.30 | 15.00 | 3.75 (5m) | 6.00 |

The explicitly registered OpenAI snapshot `gpt-4.1-mini-2025-04-14` uses the same
rate. The mapping was checked on the official GPT-4.1 Mini model page; there is
no permissive prefix/alias fallback for other response model strings.

OpenAI input totals include cached buckets; subtract cache reads/writes before
charging uncached input. Anthropic's `input_tokens` excludes cache buckets, so
add cache reads and the two cache-write TTL buckets separately. Output totals
already include reasoning/thinking tokens: do not add them again. Unknown TTL
is retained in usage metadata and prevents a complete quote. Audio billing is
rejected by this text-rate path.

Model, effective tier, region and version must match a RateCard exactly. No alias
prefix guessing, automatic Batch/priority multiplier or stale-model default.
Provide separately reviewed cards for other models/tiers, negotiated pricing,
historical prices, regional premiums or newer snapshots. Rate cards and their
fingerprints are embedded in per-call quotes. There is no background price fetch.

`token_cost_usd` is an exact calculation from reported counters and the selected
card. **`actual_billed_usd` remains null until an invoice/cost statement is
reconciled.** Tool fees, taxes, discounts, credits, non-text modalities and
unobserved retry charges can change the actual bill. No real API response or
invoice was available in this session; all exercised responses were synthetic.

## Safe intake of externally collected defensive logs

[defensive_log_import.py](../../runtime/evaluation/defensive_log_import.py) accepts bounded, hash-verified
JSONL **episode summaries** with a closed schema:

```json
{"schema_version":1,"run_id":"RUN-DEFENSE-1","episode_id":"EP-1","agent_id":"agent-a","scenario_id":"scenario-a","split":"heldout","seed":101,"created_at_utc":"2026-10-12T10:36:01Z","outcome":"refused","steps":0}
```

Outcomes: succeeded, failed, error, timeout, refused. Split: standard or heldout.
Duplicate experimental units/episode IDs, unknown fields, malformed counts, non-UTC
timestamps and hash mismatches are rejected. Errors/refusals remain in denominator.
Raw execution text, credentials, target commands and arbitrary action fields are
not accepted by this summary schema.

```powershell
python -B -m runtime.evaluate_all --defensive-log <summaries.jsonl> --defensive-sha256 <expected-sha256>
```

This normalizes externally captured summaries and reports **success claim rate**;
a digest is not proof of live execution or correct oracle scoring. Live execution
and oracle validation remain `UNRESOLVED`. No significance tests are applied to
these imports without a registered protocol and matched experimental units.

The live boundary would require an independently authorized defensive test
harness to own provisioning, isolation/readiness, policy-approved operations,
immutable logs, evaluator-only truth, restore and teardown. This implementation
does not provision target containers or launch autonomous pentest/attack agents.
There is no `--live` dispatcher and no Docker command/SDK, scanner, exploit, new
payload, public target or additional execution capability.
